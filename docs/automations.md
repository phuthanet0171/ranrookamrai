# งานอัตโนมัติ (Automations)

ก่อนเปิดใช้จริง ให้ deploy เว็บและตั้ง `APP_URL` เป็น URL สาธารณะ, ตั้ง `CRON_SECRET` ค่าเดียวกันทั้งเว็บและตัวเรียก, รัน migrations ถึง `011_automation_retry.sql`, และเชื่อม LINE หากต้องการส่งเข้า LINE ไฟล์ `web/.env.local` ที่เป็น `localhost` ใช้ทดสอบในเครื่องและ GitHub Actions เรียกไม่ถึง

ตัวเรียก GitHub Actions จะ **ล้มเหลว** เมื่อยังไม่มี secrets หรือเมื่อกฎใดส่งไม่สำเร็จ ให้ดูผลใน Actions และ “ประวัติการทำงาน” บนเว็บ หากขั้นสร้างข้อความล้มก่อนเริ่มส่ง ระบบจะลองใหม่ในรอบถัดไป หากเริ่มส่งแล้วแต่เกิดข้อผิดพลาด ระบบจะไม่ส่งซ้ำอัตโนมัติเพื่อเลี่ยงข้อความซ้ำ ให้ตรวจผู้รับและกด “รันตอนนี้” หลังแก้ปัญหา

ตั้งกฎแบบ “เมื่อ … ให้ …” ได้ที่หน้า **งานอัตโนมัติ** (`/automations`)
กด **เพิ่มกฎแนะนำที่ยังไม่มี** เพื่อเพิ่มกฎทั้งสี่แบบในช่องทางเว็บครั้งเดียว กดซ้ำไม่สร้างค่าเริ่มต้นเพิ่ม และไม่เปิดกฎที่เจ้าของร้านปิดไว้ หากต้องการส่งเข้า LINE ให้เชื่อม LINE กับร้านก่อน แล้วเปลี่ยนช่องทางของกฎเป็น LINE

| กฎ | ทำอะไร | ค่าเริ่มต้น |
|---|---|---|
| เตือนเมื่อยังไม่จดยอด | ถ้าถึงเวลาแล้ววันนี้ยังไม่มีการจดยอด ส่งข้อความเตือน | 21:00 จันทร์–เสาร์ |
| สรุปตอนเช้า | ยอดขาย กำไร เงินขาดของเมื่อวาน + วันนี้ควรเตรียมอะไร | 08:00 จันทร์–เสาร์ |
| แจ้งเตือนเงินขาด | เงินที่นับได้น้อยกว่ายอดขายเกินที่กำหนด | 22:00 ทุกวัน, ฿100 |
| สรุปรายสัปดาห์ | 7 วันที่ผ่านมาเทียบกับสัปดาห์ก่อน | 08:30 วันจันทร์ |

ข้อความสร้างจากตัวเลขในฐานข้อมูลโดยตรง **ไม่ผ่าน AI** การแจ้งเตือนตามเวลาจึงไม่มีตัวเลขที่ถูกแต่งขึ้น
ส่งได้ 3 ช่องทาง: แจ้งเตือนในเว็บ, LINE (ทุกคนที่เชื่อมกับร้าน ดู [line.md](line.md)) หรือ Discord · สรุปตอนเช้าเขียนโดย AI (ตัวเลขเติมจากฐานข้อมูล ถ้า AI ไม่ผ่านการตรวจจะส่งข้อความจากระบบแทน)

## ใครเป็นคนเรียกตามเวลา

เว็บมี endpoint เดียว `GET /api/cron` ที่ตรวจว่ากฎไหนถึงเวลาแล้ว (เวลาไทย) และยังไม่ได้รันวันนี้ แล้วรันกฎนั้น
**ต้องมีอะไรสักอย่างเรียกมันทุก 5–15 นาที** เลือกได้:

1. **GitHub Actions (ฟรี แนะนำ)**: มีไฟล์ `.github/workflows/cron.yml` อยู่แล้ว
   ตั้ง Secrets ของ repo: `APP_URL` = URL ของเว็บที่ deploy แล้ว และ `CRON_SECRET` = ค่าเดียวกับใน `web/.env.local`
2. **Vercel Cron**: `web/vercel.json` ตั้งให้เรียกวันละครั้ง 08:00 (แผนฟรีของ Vercel รันได้วันละครั้ง) ใช้เป็นตัวสำรอง
3. **n8n**: Schedule Trigger ทุก 15 นาที → HTTP Request `GET {APP_URL}/api/cron` พร้อม header `Authorization: Bearer <CRON_SECRET>`

ถ้ามีหลายตัวเรียกพร้อมกัน `automation_claim()` ในฐานข้อมูลให้สิทธิ์รันของวันนั้นกับผู้เรียกคนแรกคนเดียว ส่วนการส่งไปหลายคนที่หยุดกลางทางอาจมีบางคนได้รับแล้ว จึงต้องตรวจผลก่อนกดส่งใหม่

## ทดลองบนเครื่อง

```powershell
curl.exe -H "Authorization: Bearer <CRON_SECRET>" http://localhost:3100/api/cron
```

หรือกด **“ดูตัวอย่างข้อความ”** / **“รันตอนนี้”** ในหน้างานอัตโนมัติ (การกดรันเองไม่นับเป็นการรันตามเวลาของวันนั้น)
ทุกครั้งที่กฎทำงานจะบันทึกในหน้า **ประวัติการทำงาน**
